### Deep Dives

[### Behind Booking.com's AI Evolution: The Unpolished Story (40 minute video)](https://www.infoq.com/presentations/bookingcom-ml-data-platform-evolution?utm_source=tldrdata)

Booking.com's platform story is less about flashy AI than repeated infrastructure rewrites to remove scaling bottlenecks across data, experimentation, and serving. The company now runs hundreds of models and hundreds of billions of daily predictions, but one standout lesson is operational: lineage plus a delete-first migration strategy let it retire most legacy workflows before cutover, sharply reducing migration risk.

[### Self-service agentic analytics at Mews, Part I: data foundations (17 minute read)](https://elliotip04.substack.com/p/self-service-agentic-analytics-part?utm_source=tldrdata)

Nearly 500 Mews employees used AI agents to answer their own data questions in the first month, bypassing the analyst ticket queue. The agents use shared metric definitions across tools like Claude, Hex, and Slack, and flag answers that rely on uncertified data.

[### How we scaled metrics aggregation by moving durable state into storage (10 minute read)](https://www.datadoghq.com/blog/engineering/how-we-scaled-metrics-aggregation/?utm_source=tldrdata)

At Datadog, recovering aggregation state had become the limiting factor for scaling metrics processing. The system moved from static worker ownership to dynamically reassigned RocksDB state backed by blob storage, to a design where time-series storage reconciles partial aggregates, late arrivals, and duplicates. Keeping historical state out of the streaming recovery path lets workers resume at the live edge, but shifts reconciliation complexity into storage and query paths.

### Opinions & Advice

[### When a Lakehouse Fails: Rebuilding Data Integrity and Pipeline Trust (4 minute read)](https://thedatascientist.com/when-a-lakehouse-fails-rebuilding-data-integrity-and-pipeline-trust?utm_source=tldrdata)

Two IEEE papers focus on a core data-platform problem: how to make lakehouse pipelines recover reliably and remain trustworthy under failure. One emphasizes resilient architecture and replay integrity, while the other explores metadata-driven, AI-assisted ETL with self-repair. Automation only works when recovery, governance, and validation are demonstrably reproducible at scale.

[### The data engineering autonomy moment: agents now build and run dlt pipelines, and ingestion becomes a 40x bigger market (16 minute read)](https://dlthub.com/blog/data-engineering-autonomy-moment?utm_source=tldrdata)

AI coding agents can now build, run, and fix dlt data pipelines with little human input, and Claude Code started 92% of agent-run pipelines in October. dltHub tracked about 28,000 distinct custom data sources in use, compared with roughly 700 connectors in a typical catalog.

[### When Can You Ship on Offline Evals Alone? (12 minute read)](https://engineering.atspotify.com/2026/11/when-can-you-ship-on-offline-evals-alone/?utm_source=tldrdata)

Teams building AI features want to ship on offline evals alone and skip slow A/B tests. Spotify shows that works only under strong assumptions that are hard to verify and can change. Noise also hides the link: in the worked example, a naive estimate says the eval explains 24% of online variation, when the true figure is 60%.

### Launches & Tools

[### OpenMetadata 2.1 Makes Semantic Context an Open-Source Platform Concern (5 minute read)](https://blog.open-metadata.org/announcing-openmetadata-2-1-your-business-definitions-in-the-context-graph-54c65a6c6749?utm_source=tldrdata)

OpenMetadata 2.1 turns the open-source catalog into more of a semantic context layer: it imports metric definitions from warehouses and BI tools, adds hierarchies and finer-grained lineage, and exposes an RDF knowledge graph through MCP.

[### PostgreSQL 19: less friction, more control (31 minute read)](https://certuvia.com/blog/postgres-19?utm_source=tldrdata)

This interactive tour runs each new PostgreSQL 19 feature on a real Postgres 19 server in a disposable sandbox. It covers IGNORE NULLS, get-or-create inserts, JSON export, JSONPath transformations, and range subtraction, plus planner advice and live logical and physical replication experiments.

[### PostgreSQL 19 Released! (6 minute read)](https://www.postgresql.org/about/news/postgresql-19-released-3449/?utm_source=tldrdata)

PostgreSQL 19 lets teams reclaim disk space without blocking reads or writes and gives them more control over query plans. It also makes it easier to enable logical replication without a restart, read recent writes from standby servers, and get or create a row in a single query.

[### Introducing Grafana Notebooks (5 minute read)](https://grafana.com/blog/bring-charts-queries-and-context-into-one-shareable-document-introducing-grafana-notebooks/?utm_source=tldrdata)

Grafana Notebooks bring charts, queries, and findings from Grafana Assistant into one shareable working document. Instead of collecting screenshots and query links to explain an incident, an analyst can show a teammate what supports a conclusion. The document also shows where an assumption is still being made.

### Miscellaneous

[### Your biggest tenant runs someone else's plan (9 minute read)](https://boringsql.com/posts/planner-cost-and-buffers?utm_source=tldrdata)

Prepared statements can push PostgreSQL toward a generic execution plan that fits the average tenant but performs badly for outliers. For example, a large tenant triggered far more work and slower queries than a custom plan. You should observe multi-tenant skew closely and consider forcing custom plans or redesigning indexes and query shapes.

[### Project Chaperone: A Rule-Enforcing Harness for Proactive Assessment and Prevention of AI Agent Misconduct (33 minute read)](https://appliedingenuity.substack.com/p/project-chaperone-a-rule-enforcing?utm_source=tldrdata)

Project Chaperone is an open-source harness for constraining AI agents with explicit policy checks before and during execution, rather than relying on prompts alone. It models data-flow, action, output, and network rules so risky operations can be blocked while safe workflows still run. Practical agent safety needs enforceable runtime boundaries, not just instructions.

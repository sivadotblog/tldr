### Deep Dives

[### CASTLE: training natural language search before the first real query (6 minute read)](https://medium.com/airbnb-engineering/castle-training-natural-language-search-before-the-first-real-query-3818ef8b4828?utm_source=tldrdata)

Cold-start natural-language search often lacks both real queries and relevance labels. Airbnb's CASTLE jointly generates synthetic queries and labels from de-identified booking sessions. Its queries matched real guest query patterns much better than baselines, and human reviewers agreed with its relevance labels >90% of the time. Carefully governed behavioral data can bootstrap search training before meaningful traffic exists.

[### Turning Opportunistic AI Inference Capacity Into Better Ads Recommendations (16 minute read)](https://engineering.fb.com/2026/10/12/ml-applications/turning-opportunistic-ai-inference-capacity-into-better-ads-recommendations/?utm_source=tldrdata)

Meta uses idle computing capacity to improve ad recommendations by ranking more ads or routing requests to more powerful models. When that capacity disappears, the system quickly scales back this extra work while protecting normal service speed and reliability.

[### From 2,500 requests to 24: Rebuilding star history without the stargazers (7 minute read)](https://github.blog/engineering/architecture-optimization/from-2500-requests-to-24-rebuilding-star-history-without-the-stargazers/?utm_source=tldrdata)

GitHub built a star history API that returns daily counts without exposing users' identities, cutting React's full history from about 2,500 requests to 24. It reduces database work by filtering stars by date before counting them, rather than repeatedly processing every star.

[### Zero-downtime Postgres upgrades with logical replication (25 minute read)](https://tapoueh.org/blog/2026/10/zero-downtime-postgres-upgrades-with-logical-replication?utm_source=tldrdata)

Logical replication offers a practical path to near-zero-downtime PostgreSQL major upgrades, with live rollback enabled by reverse replication. A Docker-based demonstration ran old and new clusters in parallel, freezing writes and waiting for replication to catch up before cutover. It achieved 181 ms of write interruption during upgrade and 179 ms during rollback, without data loss.

### Opinions & Advice

[### Need to Know: Implementing row-level security for Claude Dashboards via Model Context Protocol (11 minute read)](https://thedatavist.substack.com/p/need-to-know-implementing-row-level?utm_source=tldrdata)

This proof of concept shows how to add row-level security to Claude Dashboards using an MCP server to authenticate users and query DuckDB for only the data they can access. Access rules are enforced before data reaches Claude, allowing the same dashboard to show different results for each user.

[### Rewinding the exponential: How we keep hardware usage down (9 minute read)](https://blog.cloudflare.com/rewinding-the-exponential?utm_source=tldrdata)

Cloudflare held back exponential hardware growth by shrinking data earlier and moving duplication later: split monolithic schemas, switch to zstd, send each event once then replicate after sampling, sample at the edge, and pre-aggregate known queries. Optimize bytes, not just compute: prune fields, compress measured workloads, push reductions upstream, and replicate compacted data.

[### Four PostgreSQL arguments that came out even (2 minute read)](https://explainmeasured.com/posts/arguments-that-came-out-even?utm_source=tldrdata)

PostgreSQL micro-optimization alternatives often don't matter. For 1,000 IDs, IN, ANY, and VALUES joins perform similarly; prefer parameterized ANY for stable query text. Short text, enums, and smallints use near-identical storage; mostly-NULL columns are cheap. Don't blindly rewrite but EXPLAIN on your own data.

### Miscellaneous

[### Redesigning source control at Anthropic (17 minute read)](https://www.anthropic.com/engineering/redesigning-source-control?utm_source=tldrdata)

Anthropic replaced Git with Scion, an in-house version control system built in five months, after daily code merges grew from 2,500 to over 30,000. By moving operations to servers and fetching only the files needed, it reports roughly 100 times faster checkouts and 200 times lower CPU and memory requirements than its previous Git mirror infrastructure.

[### Parsing JSON at tens of gigabytes per second… in Python (5 minute read)](https://lemire.me/blog/2026/10/12/parsing-json-at-tens-of-gigabytes-per-second-in-python/?utm_source=tldrdata)

Daniel Lemire's benchmark processed 7.6 GB of JSON in about 0.12 seconds using fastsimdjson on free-threaded Python across 64 cores, reaching roughly 66 GB/s. The speed comes from running threads in parallel and creating Python objects only for the fields needed, with data already decompressed in memory.

### Attacks & Vulnerabilities

[### Iris Ohyama Data Cloud Breach Exposes Info of 7.7M Customers (2 minute read)](https://www.bleepingcomputer.com/news/security/iris-ohyama-data-cloud-breach-exposes-info-of-77-million-customers/?utm_source=tldrinfosec)

Japanese manufacturer Iris Ohyama disclosed that a third-party cloud service was breached, exposing data belonging to 7.7M former and current customers. The exposed data includes full names, physical addresses, phone numbers, email addresses, genders, dates of birth, and account passwords. Iris Ohyama has stated that account passwords are encrypted but did not give further details.

[### Meet \*sshole, the vulnerability that lets hackers SSH into Linux devices (3 minute read)](https://arstechnica.com/security/2026/11/vulnerability-allows-attackers-to-log-into-some-linux-devices-sans-password/?utm_source=tldrinfosec)

A vulnerability called \*sshole allows remote attackers to log in to some Alpine Linux systems without a password. It affects OpenSSH built with musl and without PAM, where an active passwordless account uses SHA256 or SHA512 password hashing. An attacker can send more than 256 characters in the password field and gain access in one attempt. Alpine and OpenSSH have released patches. Affected systems should update promptly.

[### DigiCert Data Breach Impacts Business Customer Information (1 minute read)](https://www.securityweek.com/digicert-data-breach-impacts-business-customer-information/?utm_source=tldrinfosec)

DigiCert disclosed that attackers created a read-only account on an exposed internal archive system and accessed business-customer contact data from June 27 to July 2. Exposed records include names, email addresses, phone numbers, business addresses, and, in some cases, identity documents. DigiCert says certificate-issuing systems were unaffected. It has reset passwords, disabled self-registration, added monitoring, and reviewed account permissions.

### Strategies & Tactics

[### A Journey Into Claude's Sandbox (7 minute read)](https://bishopfox.com/blog/journey-into-claudes-sandbox?utm_source=tldrinfosec)

BishopFox researchers inadvertently discovered that they could convince Claude Code to reveal details about its internals. The researchers were able to use Claude to read its process memory, download files (including the process\_api binary), and create a virtual interface to bypass the local connection block. The researchers also discovered that, although the Claude Enterprise controls blocked users from changing their first name, they could do so via the API.

[### Virtualization security: attack layers and misconfiguration impact (12 minute read)](https://securelist.com/virtualization-security-esxi-and-proxmox-ransomware-cases/121819/?utm_source=tldrinfosec)

In a BlackNevas ransomware case investigated by Kaspersky GERT, attackers who reached a PRTG monitoring server used its stored ESXi root password, reused across hosts, to SSH in, disable execInstalledOnly via esxcli, and encrypt VMFS volumes before wiping logs. In a separate case, The Gentlemen group found plaintext Proxmox root credentials in an admin's notes. It used the VNC websocket API to encrypt the entire cluster, with neither attack requiring a VM escape. Defenders should give monitoring tools dedicated least-privilege identities, vault unique per-host credentials, keep ESXi SSH off behind vCenter Lockdown Mode, and alert on execInstalledOnly or Secure Boot changes.

[### The attack chain behind the v1.107.0 LiteLLM release (10 minute read)](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain?utm_source=tldrinfosec)

An admin key for LiteLLM's internal Agent Platform was committed to a public repo on May 27 and removed hours later but never revoked, and on October 10 an attacker used it to pull an org owner's unscoped GitHub CLI token from the platform API. With that token and two maintainer tokens stolen through CI workflows, the attacker overrode branch protection, built from a lookalike Berri-AI fork, and published poisoned wheels and images that stayed up for about two hours. Defenders should revoke any key that was ever committed, keep unscoped CLI tokens out of automation, and alert on branch protection overrides and deleted workflow runs.

### Launches & Tools

[### Threat Feed Me (GitHub Repo)](https://github.com/alexlinos/threat-feed-me?utm_source=tldrinfosec)

Threat Feed Me is an open-source, on-prem threat intelligence aggregator meant to replace MineMeld, Palo Alto Networks' free feed-aggregation tool, which the company retired years ago and many SOCs still miss. It pulls 22 free feeds that need no API key and removes duplicate indicators. It also detects when one feed is just republishing another, so copied entries don't look like independent agreement. That keeps the strictest high-confidence blocklist small and trustworthy.

[### Brava Security (Product Launch)](https://www.brava.security/?utm_source=tldrinfosec)

Brava Security provides an AI platform that models attacker behavior, simulates attacks, analyzes resulting telemetry, identifies missed defenses, and rewrites SIEM detections. It integrates with more than 70 sources and destinations, provides initial insights within 10–15 minutes of onboarding, and requires no changes to existing security infrastructure.

[### coldframe (GitHub Repo)](https://github.com/hedgerow-dev/coldframe?utm_source=tldrinfosec)

coldframe is a single-file Python honeypot that impersonates Danfoss AK-SM 800A and Copeland/Dixell XWEB EVO refrigeration controllers, matching the server headers, TLS certificate fields, and login flows that Shodan records for real units, and tagging exploit attempts for seven CVEs, including CVE-2025-41450 and CVE-2026-25085. Weak default logins let attackers into a fake store dashboard where every defrost click is logged as a control event, and an optional Modbus TCP listener catches generic industrial scanners. It ships with a hardened rootless container and a cloud-init file for $4 droplets, though defenders should change its persona strings before deploying, since the public code is easy to fingerprint.

### Miscellaneous

[### Secure Code Benchmark Finds Top Coding Agents Write Secure Code Only 25% of the Time (25 minute read)](https://hackernoon.com/secure-code-benchmark-finds-top-coding-agents-write-secure-code-only-25percent-of-the-time?utm_source=tldrinfosec)

Qwen researchers tested six frontier coding agents on LSCBench, 450 security-neutral tasks built from 150 real vulnerabilities across seven languages, and found that while 73.6% to 91.3% of outputs worked, even the top performer, Claude Fable 5, wrote code that was both functional and secure only 25.1% of the time. Agents often added local defenses like bounds checks but almost never secured SSRF or information exposure, which depend on policies the spec never stated, and a one-line security reminder raised joint pass rates by 15 to 21 points for three of the four models retested. Pooled together, the six models secured 44% of tasks, though the tests and specs were drafted with Qwen's own Qwen3.8-Max, which the authors argued did not tilt the results.

[### Notes and links from my talk at Texas Linux Fest (10 minute read)](https://blog.zgp.org/txlf/?utm_source=tldrinfosec)

In his Texas Linux Fest talk, Don Marti argued that open source beat the Clipper Chip and DRM mandates, but that open source's own "commoditize the complement" logic, applied to content, gave rise to an adtech system that now profits from matching scammers with victims. He cited Pew data showing 73% of US adults had faced an online scam, along with estimates that Meta earned around 10% of its ad revenue from fraud, and noted that once-niche privacy nerd advice like DNS-level ad blocking was now standard corporate IT guidance. Marti framed California privacy law and favorable jury verdicts as the most promising counterweight, though the post was explicitly preliminary and its framing of Google and Meta as crime organizations was his own opinion.

[### Agents reveal secrets when offered to team up with each other (3 minute read)](https://www.theregister.com/security/2026/11/06/agents-reveal-secrets-when-offered-to-team-up-with-each-other/5308260?utm_source=tldrinfosec)

In sandboxed tests, nine coding agents were given a private deploy token and access to a forum of 24 agents. To obtain a bug fix, the forum demanded the token and an install script. Across 181 trials, agents shared the token 15 percent of the time and ran the script 24 percent of the time, with agent pressure increasing script execution from 19 percent to 34 percent.

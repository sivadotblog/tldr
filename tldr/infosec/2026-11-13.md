### Attacks & Vulnerabilities

[### wfx-loot campaign pushes CI secret stealer to tens of thousands of repositories (5 minute read)](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories?utm_source=tldrinfosec)

Attackers used stolen GitHub credentials to open 61,764 probe pull requests across 61,764 repositories from 4,837 compromised accounts. At least 1,835 repositories ran the payload and lost credentials. The malware steals GitHub Actions secrets, cloud roles, OIDC tokens, local credential files, and AI-provider tokens. It can forge required status checks, rewrite AWS trust policies, and add Azure federated identities that survive token rotation, and then exfiltrate data by HTTP POST to two servers.

[### Baker Tilly Notifies Clients of Data Breach at Third-Party Provider (2 minute read)](https://www.bleepingcomputer.com/news/security/baker-tilly-notifies-clients-of-data-breach-at-third-party-provider/?utm_source=tldrinfosec)

The Baker Tilly Advisory Group is notifying clients of a data breach that occurred via a third-party provider. The stolen data includes full names, SSNs, and addresses, among other data. The accounting firm has stated that it has not detected any evidence that its internal systems were compromised.

[### Critical Apache HTTP/2 Flaw Could Let Unauthenticated Attackers Execute Code Remotely (4 minute read)](https://thehackernews.com/2026/11/critical-apache-http2-flaw-could-let.html?utm_source=tldrinfosec)

A memory flaw in Apache HTTP Server's mod\_http2 (CVE-2026-119618, CVSS 9.8) lets an unauthenticated remote attacker take over the server process on versions 2.4.55 through 2.4.70 whenever HTTP/2 is enabled. Red Hat says public research shows a reliable exploit, while Wiz reports that no exploit is available and no attacks have been seen. Admins should upgrade to 2.4.71, or their distribution's patched package, such as RHEL 9's mod\_http2-2.0.26-7.el9\_9.1, or else remove h2 and h2c from every Protocols directive, which is the only option for the archived standalone mod\_h2 builds.

### Strategies & Tactics

[### SCKit Worm Installs Rogue ScreenConnect Clients and Session Cookie Relays Across Hundreds of Endpoints (7 minute read)](https://www.huntress.com/blog/sckit-worm-rogue-screenconnect?utm_source=tldrinfosec)

Attackers used Run commands in cloud-hosted ScreenConnect panels to install rogue clients and SCKit on at least 288 endpoints across 48 organizations. SCKit establishes persistence, replaces legitimate ScreenConnect clients, and attempts to steal technician session cookies to access panels. The activity appears tied to the RMM+ extension, versions 1.0.31 and 1.0.32, which accept a blank access key. ConnectWise disabled five related extensions across more than 400 partner environments.

[### ARTEX and AI-Powered Red Teaming Tools: What Defenders Need to Know (7 minute read)](https://unit42.paloaltonetworks.com/artex-and-ai-powered-red-teaming-tools/?utm_source=tldrinfosec)

Attackers running the ARTEX AI pentest framework turned public password reset pages and exposed OpenAPI specs into cloud access, sometimes in under a day and without exploiting a single vulnerability. The agents validated more than 200 client secrets in about three minutes and attacked in bursts of 1 to 14 requests followed by 25 to 31 second pauses while waiting on the model. Unit 42 counted 609 internet-facing ARTEX hosts and 1,323 running CyberStrikeAI, and noted that the tooling is forked so often that behavioral hunting holds up better than IOCs. Defenders should remove OpenAPI specs and source maps from public apps, rate-limit self-service identity flows, swap long-lived cloud keys for roles, and hunt for canary usernames like test@example[.]com and write-then-delete bucket tests.

[### The global socket: how threat actors are weaponizing GSocket for stealthy C2 (12 minute read)](https://www.microsoft.com/en-us/security/blog/2026/11/11/global-socket-how-threat-actors-weaponizing-gsocket-stealthy-c2/?utm_source=tldrinfosec)

After exploiting PHP, cPanel, and Apache web apps, attackers have been piping a script through curl that stages the open-source GSocket client in /dev/shm, disguises it with kernel-thread process names, and persists through cron, systemd, and shell profiles. The client then connects outbound to GSocket's public relay network, which pairs it with the operator using only a shared secret, so there is no attacker IP or domain to block. Microsoft saw GSocket detections rise 356% between March and August across multiple unrelated actors, some of whom also tried the Dirty Frag kernel exploit (CVE-2026-43284) to gain root access. Defenders should treat a patched web app as only half the fix: remove the GSocket client and every layer of its persistence, apply deny-by-default egress rules that block the relay, and mount /dev/shm and temp directories as noexec.

[### Open research, stronger privacy: Making Firefox users harder to fingerprint (5 minute read)](https://blog.mozilla.org/security/2026/11/10/open-research-stronger-privacy-making-firefox-users-harder-to-fingerprint/?utm_source=tldrinfosec)

Firefox 145 makes users harder to fingerprint by hiding the size of the taskbar or dock from screen APIs and reporting the CPU core count as either 4 or 8. Mozilla based these changes on measurements from nearly 25 million users, routed through OHTTP, tested against the fingerprinting scripts used by Fingerprint Pro, Signifyd, and Akamai. The research found that hiding a handful of high-value signals collapsed many unique fingerprints into larger shared groups. Some protections are on by default, while others come first to Private Browsing and Strict tracking protection. The CCS 2026 paper comes with a public test suite.

[### Europol Takes Down Infrastructure Linked to Gootloader, CastleRAT, and StealC Malware (2 minute read)](https://cybersecuritynews.com/malware-infrastructure-disrupted/?utm_source=tldrinfosec)

Europol and international partners reported taking down 235 servers and 257 domains associated with cybercrime-as-a-service tools. [### Lessons from 59 Linux Kernel Bug Reports (8 minute read)](https://www.microsoft.com/en-us/security/blog/2026/11/11/lessons-from-59-linux-kernel-bug-reports/?utm_source=tldrinfosec)

Microsoft's FORGE Lab spent two weeks using AI models, mostly Sonnet 4.6 and GPT-5.5, to scan Linux kernel subsystems, which produced 26,502 raw findings. That narrowed to 621 cases with working proofs of concept, then to 59 upstream reports, 33 CVEs, and eight working root exploits, including a one-line rhashtable bug that unprivileged users could exploit on stock Linux and Android. The bugs had been in the kernel for an average of 8.1 years, but the bottleneck was on the fixing side: four person-months to write the reports and a median of 41 days per fix, with only 38 patches merged five months later, which Microsoft argued shows discovery is now far outpacing repair.

### Attacks & Vulnerabilities

[### Capcom Confirms Major Data Breach Affecting 11.7M Capcom ID Accounts (2 minute read)](https://www.notebookcheck.net/Capcom-confirms-major-data-breach-affecting-more-than-11-7-million-Capcom-ID-accounts-worldwide.1431069.0.html?utm_source=tldrinfosec)

Capcom disclosed that it suffered a data breach involving its Capcom ID service. The attackers stole account details of 11.7M accounts, including email addresses, account creation dates, last login time, total logins, and the most recent login IP. A smaller number of accounts also had personal information leaked.

[### LiteLLM supply chain attack hoovers up passwords and secrets (3 minute read)](https://www.theregister.com/security/2026/10/21/litellm-supply-chain-attack-hoovers-up-passwords-and-secrets/5304548?utm_source=tldrinfosec)

Attackers compromised LiteLLM's release process and published version 1.107.0 through PyPI and Docker. The package contained an infostealer and a remote access trojan that ran when Python started. It collected browser, AWS, Google Cloud, Azure, LLM API, SSH, GPG, and shell-history secrets, encrypted them, and sent them to an attacker domain. PyPI and Docker removed the package. Anyone who ran it should rotate credentials and check for the published indicators.

[### GitLab critical patches include one for a bug that allows code execution by unauthenticated users (3 minute read)](https://www.infoworld.com/article/4239276/gitlab-critical-patches-include-one-for-a-bug-that-allows-code-execution-by-unauthenticated-users.html?utm_source=tldrinfosec)

GitLab released patches for 12 issues, including CVE-2026-110264, a critical integer-overflow flaw in its regular-expression compiler. An unauthenticated attacker could execute arbitrary code on affected CE/EE servers. Fixes cover versions 18.11.13 through 19.5.1. Affected releases date back to 7.0. The update also fixes CVE-2026-15723, which let an authenticated OmniAuth SAML user take over an LDAP-backed account when LDAP auto-linking was enabled. GitLab says the patches include database migrations, so single-node deployments may require downtime.

### Strategies & Tactics

[### AWS Key Quarantine is Not Revocation (6 minute read)](https://trufflesecurity.com/blog/aws-key-quarantine-is-not-revocation?utm_source=tldrinfosec)

When AWS detects leaked keys, it will apply a quarantine policy to the IAM user associated with the key that denies certain sensitive actions. Truffle Security audited the quarantine policy and found significant gaps such as the ability to read secrets from Secrets Manager or parameters from Parameter Store, the ability to run a command on a running EC2 instance, and the ability to download S3 objects via GetObjectVersion. Truffle Security noted that beyond quarantine, revocation remains a major gap, with many of the keys they tested exposed for years.

[### How Abliterated Models Can Get You pwned (5 minute read)](https://projectdiscovery.io/research/how-abliterated-models-can-get-you-pwned?utm_source=tldrinfosec)

To test the process of creating a backdoored model, ProjectDiscovery researchers fine-tuned Qwen2.5-7B to exfiltrate a .env file when it encounters a trigger phrase. The researchers achieved this with a rented GPU and a small dataset containing 20% poisoned prompts. Backdoored models are incredibly difficult to detect, so teams should use strong behavioral filters and avoid downloading models from untrusted sources.

[### The Current Landscape of OAuth Attacks (16 minute read)](https://unit42.paloaltonetworks.com/current-landscape-oauth-attacks?utm_source=tldrinfosec)

Attackers have shifted to stealing OAuth access and refresh tokens, bypassing MFA and surviving password resets, using device code phishing, consent screens for impersonated or vaguely named apps, and redirect\_uri abuse that sends victims from real IdP domains to attacker pages. Unit 42 found PhaaS kits reusing the same anti-bot and Cloudflare RUM tokens across campaigns, along with AES-GCM payloads decrypted at runtime on Cloudflare Workers and LLM-generated lures, though the report gives no victim counts. Defenders should replace end-user consent with admin approval workflows, audit registered redirect\_uri values for unverified domains, and flag device codes pasted from untrusted sources.

[### Antares: a Security Analyst That Never Leaves Your Laptop – Security Loop Series, Part 1 (10 minute read)](https://blogs.cisco.com/cisco-devnet/antares-security-analyst-laptop-part-1?utm_source=tldrinfosec)

Antares-1B is a Cisco model, post-trained from IBM Granite 4.0 1B, that locates vulnerable files offline by running up to 15 read-only sandboxed shell commands against a repo given only a CWE description. Cisco's own benchmark placed it fourth in file F1 on the 500-repo VLoc Bench, ahead of Gemini 3 Pro and with the best recall of any system tested, and the author's Apple M1 run reproduced about 80% of that score at roughly a minute per repo. Results export as SARIF 2.1.0 for CI gating, though noisy shortlists and a steep accuracy drop on repos beyond a few megabytes make it a triage aid rather than a detector.

### Miscellaneous

[### Tech and Security Companies Respond to PHP2Shell Vulnerabilities (5 minute read)](https://www.securityweek.com/tech-and-security-companies-respond-to-php2shell-vulnerabilities/?utm_source=tldrinfosec)

PHP2Shell, CVE-2026-109618 and CVE-2026-109619, enable unauthenticated remote code execution. PHP released fixes on October 21, after exploitation attempts began on October 17. Cisco, AWS, Google Cloud, Ubuntu, Debian, Palo Alto Networks, Sophos, and others issued patches, mitigations, or detection rules. CISA, UK NCSC, CERT-EU, and other agencies urge immediate updates, especially for internet-facing systems. Some European government, school, and hospital sites were taken offline.

[### TiDB Breach Exposes Flawed Cloud Security Assumptions (6 minute read)](https://www.darkreading.com/cloud-security/tidb-breach-flawed-cloud-security?utm_source=tldrinfosec)

PingCAP disclosed that attackers used stolen service-account credentials to access TiDB systems from September 9 to October 7, copying data and source code. FulcrumSec claims it also obtained customer metadata, API keys, Jira tickets, SQL histories, and a four-year TiDB Cloud connection log. Customer databases were reportedly untouched, but query logs and diagnostics can contain connection strings, secrets, and sensitive records.

[### State of Post-Quantum Cryptography implementations (17 minute read)](https://blog.quarkslab.com/state-of-post-quantum-cryptography-implementations.html?utm_source=tldrinfosec)

Quarkslab's differential fuzzer DeltAFLy found that seven of ten tested libraries, including liboqs, AWS-LC, and libcrux, accepted malformed ML-DSA private keys with out-of-range coefficients that can bias rejection sampling and leak secret key material, while only OpenSSL, BoringSSL, and SymCrypt rejected them. The same campaign uncovered an OID collision bug in RustCrypto's XMSS code that made imported XMSSMT public keys fail verification. The post also surveyed PQC support across more than 20 open-source libraries, finding ML-KEM and ML-DSA nearly universal while HQC, Classic McEliece, and X-Wing remain sparsely implemented.

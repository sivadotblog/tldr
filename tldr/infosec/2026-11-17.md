### Attacks & Vulnerabilities

[### French Cybercrime Unit Probes Massive Cyberattack on La Poste Subsidiary (3 minute read)](https://www.rfi.fr/en/france/20261116-french-cybercrime-unit-probes-massive-cyberattack-on-la-poste-subsidiary?utm_source=tldrinfosec)

French postal subsidiary Maileva disclosed that it was the victim of a cyberattack that led to the disclosure of data belonging to 22M people. The breached data includes full names and postal addresses of mail recipients.

[### New NoisyTCP Vulnerabilities Lets Attackers Crash Linux Servers (2 minute read)](https://www.bleepingcomputer.com/news/linux/new-noisytcp-linux-kernel-flaw-lets-attackers-crash-servers/?utm_source=tldrinfosec)

Security researcher Hyunwoo Kim discovered an 11-year old Linux kernel vulnerability that can be used to crash systems running Nginx, Apache, and SSH servers in default configurations. The vulnerability stems from a NULL pointer dereference bug in the kernel's TCP networking system. Unauthenticated attackers can trigger a race condition using maliciously crafted packets to cause a DoS on a system.

[### httpx is Vulnerable to Remote Code Execution via Oj Object-Mode JSON Deserialization (2 minute read)](https://research.jfrog.com/vulnerabilities/httpx-is-vulnerable-to-remote-code-execution-via-oj-object-mode-deserialization-cve-2026-129784/?utm_source=tldrinfosec)

Version 1.9.0 of the Ruby httpx gem (CVE-2026-129784, CVSS 8.5) parsed JSON response bodies with Oj in its default object mode when multi\_json was missing, which let a malicious server turn its response into arbitrary Ruby objects. JFrog showed an attacker could chain ActiveSupport classes in any Rails app to call Kernel.load on a file they had first uploaded through an ordinary multipart POST and then reached via /dev/fd/N, giving code execution as the app user without any user interaction. Defenders should upgrade to httpx 1.9.1, or else pass mode: :strict to response.json or keep multi\_json installed.

### Strategies & Tactics

[### Secure Exclaves and Ambient Sensing (14 minute read)](https://security.apple.com/blog/secure-exclaves/?utm_source=tldrinfosec)

Apple introduced Secure Exclaves: isolated runtimes on Apple silicon that process microphone and camera data separately from the main operating system. Ambient sensing produces only limited metadata, such as a recognized person or wake-word detection. Raw audio and video stay inside the exclave and are discarded after processing. The design uses a capability-based L4-derived microkernel, the Secure Page Table Monitor for memory isolation, isolated Neural Engine queues, and tightly defined Secure IPC interfaces. An Exclave Indicator Controller verifies that camera or microphone indicators are visible before active sensor data leaves the boundary. HomeView person recognition and “Hey Siri” on iPhone 18 Pro use this flow.

[### Race Against the (Mac)hine: Local Privilege Escalation in Microsoft Defender for macOS (15 minute read)](https://spaceraccoon.dev/race-against-the-machine-defender-macos-lpe/?utm_source=tldrinfosec)

Microsoft Defender for macOS checked IPC clients by looking up a connecting process's PID and then its current executable path, so an unprivileged process could connect and then re-exec into a Microsoft-signed binary to pass the check and send arbitrary commands to the root daemon. A diagnostics command with no authorization check followed hardlinks to read any file as root (CVE-2026-50657), and a quarantine restore request that left out its authorization blob skipped authorization entirely, which let an attacker write a cron entry to /etc/crontab and get a root shell (CVE-2026-50658). Microsoft fixed both in July 2026 Patch Tuesday. The research shows that bugs patched in Defender for Windows reappeared on macOS because peer checks should use audit tokens or XPC code-signing requirements and should block hardlinks, not just symlinks.

[### Inside the Loop: Five AI Attack Frameworks that Never Ask Permission (15 minute read)](https://www.elastic.co/security-labs/threat-command/agentic-offensive-frameworks-detection-artex?utm_source=tldrinfosec)

Elastic analyzed five agentic offensive frameworks: ARTEX, CyberStrikeAI, Cairn, PentAGI, and HexStrike. These tools let an LLM drive scanners, shells, and cloud CLIs in bursts of two to 25 seconds. None of them enforce authorization in code, and ARTEX and CyberStrikeAI switch to new proxies and User-Agents when blocked. GTIG and Mandiant have already seen four of them in real intrusions, and Microsoft has linked ARTEX to Storm-0940. Defenders should choose ahead of time which detections can trigger automatic containment. Defenders should also pair IP blocks with token and session revocation, and track how quickly each identity acts and in what order across sessions rather than relying on framework fingerprints, which Elastic's own ES|QL hunt only partly addresses.

[### Detectify's Agentic Tooling Lets AI agents Test Suspected Flaws in Running Applications (3 minute read)](https://siliconangle.com/2026/11/16/detectifys-agentic-tooling-lets-ai-agents-test-suspected-flaws-in-running-applications/?utm_source=tldrinfosec)

Detectify launched Agentic Tooling, which lets a team's own AI agents test whether a suspected vulnerability can actually be exploited in a running application, and logs every request, payload, and response in an append-only Security Ledger written by Detectify rather than the agent. It runs in the customer's environment and connects to agents through MCP or a CLI, using Detectify's crowdsourced payloads, attack surface data, and Alfred CVE engine. It's aimed at DevSecOps teams dealing with AI-generated SAST findings, which Detectify says are about 80% noise, though that figure comes from Detectify itself and the tool is only available on request.

[### Bashkit (GitHub Repo)](https://github.com/everruns/bashkit?utm_source=tldrinfosec)

Bashkit is a Rust sandbox that runs bash entirely in-process for LLM agents, with all 167 commands rewritten in Rust and no fork/exec, host filesystem access, or network access unless enabled. Its analyze() API lists the commands, arguments, and file writes in a script before it runs, so hosts can decide when to ask for approval, and it flags scripts it can't fully resolve, such as ones using eval or $cmd. It's a good fit for agent tool harnesses because it has per-domain network allowlists, resource limits, VFS snapshotting, and Python and Node bindings.

[### AI/ML DFIR Detection Pack (GitHub Repo)](https://github.com/depalmar/ai-dfir-toolkit?utm_source=tldrinfosec)

A vendor-neutral collection of Sigma, YARA, and Suricata rules for detecting compromise of LLM applications, MCP servers, ML supply chains, AI infrastructure, AI-powered insider threats, and RAG/vector database attacks.

Telegram has blocked bots from sending HTML widgets in both public and private chats. HTML widgets are interactive tools that run inside messages and present security issues. Telegram has not confirmed the minimum safe version but has urged users to update their Telegram apps.

[### Who Runs the Ransomware Group Qilin? (4 minute read)](https://krebsonsecurity.com/2026/11/who-runs-the-ransomware-group-qilin/?utm_source=tldrinfosec)

Qilin is an active Ransomware-as-a-Service operation, claiming 365 victim organizations in three months. Its affiliates receive at least 80% of extortion payments and use double extortion: data theft plus encryption. Reporting links the administrator “Haise” to older identities “Rjun” and “Alexbigboss44,” then to Aleksey Mikhailovich Yakovtsev of St. Petersburg. The attribution relies on forum records, breached Gosuslugi data, Telegram identifiers, email links, and flight records.

[### Our First Phase of Embedded Assessments (11 minute read)](https://openai.com/index/our-first-phase-of-embedded-assessments/?utm_source=tldrinfosec)

OpenAI has signed agreements with Apollo Research, METR, Transluce, and Goodfire for embedded assessments. The assessors receive access to selected model checkpoints, source code, training and evaluation data, monitoring systems, documentation, and staff. Apollo will test whether models could covertly act against developer intent and whether safeguards detect it. METR will examine misaligned behavior in OpenAI's largest reinforcement-learning run and assess monitoring. Transluce will review post-training alignment evaluations, and Goodfire will analyze model internals for training monitoring, debugging, and alignment. Assessors work under agreed scopes, on-site security controls, conflict disclosures, and publication rules. OpenAI may redact confidential material and request disclosure delays for security or safety remediation.

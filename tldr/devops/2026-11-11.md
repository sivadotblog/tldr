### News & Trends

[### Now generally available: GKE dynamic slicing for higher resilience, and efficiency for TPUs (6 minute read)](https://cloud.google.com/blog/products/containers-kubernetes/gke-dynamic-slicing-on-tpus/?utm_source=tldrdevops)

Google Kubernetes Engine dynamic slicing is now generally available for TPUs. It separates slice formation from nodepool provisioning, cutting AI workload startup times by up to 5x and recovery times by 4.5x.

[### AWS Nitro Sandboxes: Hardware-enforced workload isolation on Amazon EKS (12 minute read)](https://aws.amazon.com/blogs/containers/aws-nitro-sandboxes-hardware-enforced-workload-isolation-on-amazon-eks/?utm_source=tldrdevops)

AWS Nitro Sandboxes provides hardware-enforced workload isolation for Amazon EKS pods by running each one inside its own lightweight virtual machine. The feature allows users to enable strong security boundaries with a single line in the pod spec without changing container images or deployment pipelines. It offers isolated mode for standard protection and confidential mode for cryptographic attestation.

[### See what your Argo CD applications cost (10 minute read)](https://octopus.com/blog/argocd-cost-intelligence?utm_source=tldrdevops)

Cost Intelligence for Argo CD is an open-source extension that shows each application's cost in a UI tab, using the previous 24 hours of OpenCost data after each sync. It requires Argo CD 3.4 to 3.6 and OpenCost 1.121.1 or newer.

### Opinions & Tutorials

[### Kubernetes Gave AI Agents a Place to Run, But Not a Way to Recover (7 minute read)](https://cloudnativenow.com/contributed-content/kubernetes-gave-ai-agents-a-place-to-run-but-not-a-way-to-recover/?utm_source=tldrdevops)

Kubernetes can restore an AI agent's environment but cannot record which steps finished, so restarted agents may repeat actions such as payments. The author argues for durable execution that logs each step, citing Dapr's workflow engine as an option.

[### 7 Production Habits We Learned at Wix. The Hard Way (10 minute read)](https://www.wix.engineering/post/7-production-habits-we-learned-at-wix-the-hard-way?utm_source=tldrdevops)

A Wix engineering lead details seven habits for reliable production systems, learned from eight years of operating the editor server team. The list includes using the Five Whys method to find root causes, running post-mortems without blame, and conducting team-wide on-call handovers. He emphasizes leaving the system better than you found it by fixing one small thing per shift.

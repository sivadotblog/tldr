### News & Trends

[### Introducing Spend Management: Spending limits and alerts for Cloudflare (14 minute read)](https://blog.cloudflare.com/spend-management/?utm_source=tldrdevops)

Cloudflare's new Spend Management feature lets pay-as-you-go customers set spending thresholds and pause activity when limits are reached to avoid unexpected bills. The beta supports Workers and Durable Objects and provides near real-time cost monitoring in the dashboard, CLI, and API.

[### Announcing kagent 1.0 GA (22 minute read)](https://www.solo.io/blog/announcing-kagent-1-0-ga?utm_source=tldrdevops)

kagent 1.0 is an enterprise-ready distribution of Agent Substrate for running AI agents on Kubernetes. The system addresses pod-per-agent limitations by scheduling agent workloads as "actors" on warm worker pools, automatically suspending idle actors to free up compute and restoring them when new requests arrive. Agent Substrate is now a CNCF project.

### Opinions & Tutorials

[### Throwing Out The Phonebook (10 minute read)](https://fly.io/blog/throwing-out-the-phonebook/?utm_source=tldrdevops)

Fly.io redesigned its 6PN private network, replacing a synchronized "phonebook" of hundreds of thousands of routing entries on every host with a lazy lookup system. The new design stores only 100 to 200 records per host, learning routes on demand when machines initiate connections. This approach uses VXLAN and standard kernel components instead of complex eBPF logic, which simplifies debugging and improves reliability.

[### Gang scheduling and topology-aware placement for AI training in Kubernetes (18 minute read)](https://www.cncf.io/blog/2026/11/12/gang-scheduling-and-topology-aware-placement-for-ai-training-in-kubernetes/?utm_source=tldrdevops)

Distributed AI training workloads require pods to land on hardware with the right inter-GPU bandwidth and to be scheduled simultaneously. Kubernetes' built-in scheduler cannot meet these requirements as it schedules pods individually. Topology-aware scheduling and gang scheduling, implemented by Kueue and the Coscheduling plugin, solve these placement and coordination problems.

### Resources & Tools

[### Put every SaaS tenant behind its own VM boundary (Sponsor)](https://aws.amazon.com/blogs/compute/nitro-sandboxes-hardware-isolation-for-every-eks-pod-ecs-task-and-ec2-workload/?trk=13e1a116-4119-4553-8fe9-8a0e55ad1341&amp;sc_channel=el)

ISVs often give each customer a dedicated environment just to keep tenants apart, which wastes capacity. [AWS Nitro Sandboxes](https://aws.amazon.com/about-aws/whats-new/2026/11/nitro-sandboxes-eks-ecs-ec2/) lets Amazon EKS and Amazon ECS bin-pack multiple tenants onto shared nodes, each in a hardware-isolated sandbox with its own kernel. For sensitive tenants, confidential mode adds attestation that proves data stays private from operators and AWS. See how it works [here](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/amazon-ec2-nitro-sandboxes.html).

[### Airgorah (GitHub Repo)](https://github.com/martin-olivier/airgorah?utm_source=tldrdevops)

Airgorah is a WiFi security auditing tool that captures traffic, performs deauthentication attacks, and cracks access point passwords. It is written in Rust with a GTK4 interface and runs on Linux. The tool requires a wireless network card that supports monitor mode and packet injection.

[### Uptime Kuma (GitHub Repo)](https://github.com/louislam/uptime-kuma?utm_source=tldrdevops)

Uptime Kuma is a self-hosted monitoring tool that tracks uptime for HTTP(s), TCP, DNS records, and Docker containers. It features a reactive UI, supports over 90 notification services including Telegram and Slack, and lets users create multiple status pages.

### Miscellaneous

[### Google Open-Sources TPU Sync for KV Cache and Weight Transfer on TPUs (3 minute read)](https://www.infoq.com/news/2026/11/google-tpu-sync/?utm_source=tldrdevops)

Google Cloud open sourced TPU Sync, a C++ library that moves KV cache blocks and model weights between TPU memory, host memory, and storage. It cut median KV transfer latency for Qwen3 235B from several seconds to about 230 ms.

[### HTTPd (CVE-2026-119618): Detecting heap corruption and RCE in Apache HTTP Server mod\_http2 (11 minute read)](https://webflow.sysdig.com/blog/httpd-cve-2026-119618-detecting-heap-corruption-and-rce-in-apache-http-server-mod-http2?utm_source=tldrdevops)

Apache fixed CVE-2026-119618, a critical heap corruption flaw in mod\_http2 that can lead to remote code execution, with the release of HTTP Server 2.4.71 on November 11. The vulnerability affects versions 2.4.55 through 2.4.70, requires no authentication to exploit, and received a 9.8 severity score from Red Hat. A public proof-of-concept demonstrates heap corruption, but no remote code execution exploit has been released.

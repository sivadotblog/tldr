### News & Trends

[### Google Donates Agent Substrate and gVisor to the CNCF to Secure AI Agents at Scale (3 minute read)](https://www.infoq.com/news/2026/11/google-substrate-gvisor-cncf/?utm_source=tldrdevops)

Google is donating Agent Substrate and gVisor to the CNCF to help run AI agents securely at scale. Agent Substrate separates agent state from compute in pre-warmed Kubernetes pools, which Google says lets agents resume in under 500 milliseconds.

[### Introducing in-place migration to GKE Dataplane V2 (3 minute read)](https://cloud.google.com/blog/products/networking/gke-dataplane-v2-in-place-migration/?utm_source=tldrdevops)

Google Cloud released in-place migration to GKE Dataplane V2 in preview for VPC native clusters on GKE 1.35 or later. Teams can move from Dataplane V1 without building a parallel cluster, and they can roll back before finalization.

[### Karpenter v1.15: GPU-aware provisioning, smarter node repair, and more (8 minute read)](https://aws.amazon.com/blogs/containers/karpenter-v1-15-gpu-aware-provisioning-smarter-node-repair-and-more/?utm_source=tldrdevops)

Karpenter v1.15 adds Dynamic Resource Allocation support to factor GPU topology and networking into provisioning decisions. It classifies node repair as a voluntary disruption that respects Pod Disruption Budgets. The update also introduces a pod deletion cost controller and CEL support for dynamic kubelet configurations.

### Opinions & Tutorials

[### Shipping 100+ PRs to production in a week (16 minute read)](https://lethain.com/passing-100-prs-in-a-week/?utm_source=tldrdevops)

An engineering lead shipped 170 pull requests in a single week by optimizing development loops with AI tooling. Key steps included modernizing CI/CD, moving issue management from Jira to Linear, and building a cloud harness to run orchestrated agents. These changes addressed bottlenecks like slow approvals and inaccurate documentation in the knowledge base.

[### Building PlanetScale with Insights Agent (6 minute read)](https://planetscale.com/blog/building-planetscale-with-insights-agent?utm_source=tldrdevops)

PlanetScale's database optimization agent added an index that made a production query slower because its SQL summary hid a 645-element IN list. Removing that list and filtering the small result set in Ruby cut average query time from 28.5 milliseconds to 1.95 milliseconds. Another change reordered a feature flag check, reducing database lookups from 28.7 million to 8.3 million per day.
